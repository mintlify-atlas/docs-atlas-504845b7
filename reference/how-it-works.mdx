---
title: "How it works"
description: "A technical walkthrough of how Kahoot Answer Bot joins a game and submits answers."
---

Kahoot Answer Bot works by mimicking a real Kahoot client: it acquires a session, solves an anti-bot challenge, connects over WebSocket, and submits answers as each question appears.

<Steps>
  <Step title="Session acquisition">
    The bot sends a GET request to Kahoot's reservation endpoint to obtain a session token:

    ```
    GET https://play.kahoot.it/reserve/session/{pin}/?{unix_timestamp}
    ```

    A successful response (HTTP 200) returns:
    - **`x-kahoot-session-token`** response header — a base64-encoded token
    - **`challenge`** field in the JSON body — JavaScript code used to derive the session ID

    If the pin does not exist or the game has not started, the endpoint returns a non-200 status and the bot exits with an error.
  </Step>

  <Step title="Challenge solving">
    Kahoot requires clients to solve a JavaScript challenge before connecting. This is an anti-bot mechanism that produces the session ID.

    **Step 1 — Execute the challenge JS**

    The raw challenge string is JavaScript code. The bot strips whitespace, reconstructs the function, and evaluates it using [`py_mini_racer`](https://github.com/sqreen/PyMiniRacer) (a Python binding for the V8 engine):

    ```python
    jsEngine = py_mini_racer.MiniRacer()
    solution = jsEngine.eval("".join(rebuilt))
    ```

    **Step 2 — XOR-shift the session token**

    The V8-evaluated solution is then used to XOR-decode the base64 session token character by character:

    ```python
    decodedToken = base64.b64decode(self.sessionToken).decode('utf-8')
    sessionID = "".join([
        chr(sessChars[i] ^ solChars[i % len(solChars)])
        for i in range(len(sessChars))
    ])
    ```

    The resulting string is the **session ID** used to open the WebSocket connection.
  </Step>

  <Step title="WebSocket connection">
    The bot connects to Kahoot's real-time game server using the [CometD](https://cometd.org/) protocol over WebSocket via the `aiocometd` library:

    ```
    wss://play.kahoot.it/cometd/{pin}/{sessionID}
    ```

    After connecting, it subscribes to three channels:

    | Channel | Purpose |
    |---|---|
    | `/service/controller` | Send commands (login, answers, 2FA) |
    | `/service/player` | Receive player-scoped events |
    | `/service/status` | Receive game status updates |
  </Step>

  <Step title="Login">
    After subscribing, the bot publishes a login event to `/service/controller`:

    ```json
    {
      "host": "kahoot.it",
      "gameid": "<pin>",
      "captchaToken": "KAHOOT_TOKEN_eyJ2ZXJzaW9uIjoiIn0=",
      "name": "<nickname>",
      "type": "login"
    }
    ```

    The server responds with a `USERNAME_ACCEPTED` (id 14) or `USERNAME_REJECTED` (id 15) event.

    <Note>
      The captcha token is hardcoded. See [Caveats](/reference/caveats) for implications.
    </Note>
  </Step>

  <Step title="Answer lookup">
    The correct answers are fetched from Kahoot's REST API using the quiz ID. This can happen in two ways:

    - **Before the game starts** — if a quiz ID (`-q`) or quiz name (`-n`) was provided at launch, the bot fetches and parses answers immediately.
    - **On `START_QUIZ` event (id 9)** — if no quiz ID was provided, the bot waits for the game host to start and then resolves answers using the `quizQuestionAnswers` payload from the event.

    The `parseAnswers` method iterates through each question's `choices` array and records the index of the first choice where `correct == true`:

    ```python
    for i, choice in enumerate(question['choices']):
        if choice['correct'] and not foundAnswer:
            answers.append({'question': ..., 'index': i, 'answer': ...})
    ```

    Only `quiz` and `multiple_select_quiz` question types are processed. All other types are skipped.
  </Step>

  <Step title="Answer submission">
    Each time a `START_QUESTION` event (id 2) is received, the bot looks up the pre-fetched answer for that question index and publishes it:

    ```json
    {
      "choice": 2,
      "meta": {
        "lag": 0,
        "device": {
          "userAgent": "kbot",
          "screen": { "width": 1920, "height": 1080 }
        }
      }
    }
    ```

    This is sent to `/service/controller` with message `id: 45` (`GAME_BLOCK_ANSWER`).
  </Step>

  <Step title="Two-factor authentication">
    Some Kahoot games require 2FA. The bot handles this flow automatically:

    1. Server sends `RESET_TWO_FACTOR_AUTH` (id 53)
    2. Bot prompts the user to enter the color sequence shown on screen in `r/b/y/g` format
    3. Input is mapped to numeric indices: `r=0, b=1, y=2, g=3`
    4. Bot submits the sequence to `/service/controller` with message `id: 50` (`SUBMIT_TWO_FACTOR`)
    5. Server responds with `TWO_FACTOR_AUTH_CORRECT` (id 52) or `TWO_FACTOR_AUTH_INCORRECT` (id 51)
  </Step>
</Steps>

## Message event codes

Kahoot's WebSocket protocol uses numeric IDs to identify event types. The bot maps these internally:

| ID | Event name |
|---|---|
| 1 | `GET_READY` |
| 2 | `START_QUESTION` |
| 3 | `GAME_OVER` |
| 4 | `TIME_UP` |
| 5 | `PLAY_AGAIN` |
| 6 | `ANSWER_SELECTED` |
| 7 | `ANSWER_RESPONSE` |
| 8 | `REVEAL_ANSWER` |
| 9 | `START_QUIZ` |
| 10 | `RESET_CONTROLLER` |
| 11 | `SUBMIT_FEEDBACK` |
| 12 | `FEEDBACK` |
| 13 | `REVEAL_RANKING` |
| 14 | `USERNAME_ACCEPTED` |
| 15 | `USERNAME_REJECTED` |
| 40 | `STORY_BLOCK_GET_READY` |
| 41 | `REACTION_SELECTED` |
| 42 | `REACTION_RESPONSE` |
| 43 | `GAME_BLOCK_START` |
| 44 | `GAME_BLOCK_END` |
| 45 | `GAME_BLOCK_ANSWER` |
| 50 | `SUBMIT_TWO_FACTOR` |
| 51 | `TWO_FACTOR_AUTH_INCORRECT` |
| 52 | `TWO_FACTOR_AUTH_CORRECT` |
| 53 | `RESET_TWO_FACTOR_AUTH` |
